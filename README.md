# Antigravity Patcher — запуск на macOS

Патчер создаёт отдельные изменённые копии Antigravity и CLI agy.
**Команду `patch` нужно выполнить один раз для каждой копии. Перед каждым запуском повторять её не нужно.**

Требуются Mac с Apple Silicon, Python 3.9+ и системная утилита `codesign`.
Установка Python-пакетов и `sudo` не нужны.

## Получение проекта

Если локальной копии проекта ещё нет:

```sh
git clone https://github.com/vexner67/agy-patcher.git ~/dev/agy-patcher
cd ~/dev/agy-patcher
```

## Antigravity: первый запуск

1. Закрой запущенный Antigravity.
2. Открой Терминал и выполни:

   ```sh
   cd ~/dev/agy-patcher
   python3 -B agy_patcher.py inspect --target app
   python3 -B agy_patcher.py patch --target app --output-dir ./build-app
   ```

   `inspect` проверяет совместимость без изменений. Если он сообщает об ошибке,
   создание копии следует остановить: эта сборка не поддерживается.

3. После успешного создания открой копию:

   ```sh
   open -n ~/dev/agy-patcher/build-app/Antigravity.app
   ```

Исходное приложение `/Applications/Antigravity.app` остаётся неизменным.

## Antigravity: обычный запуск

Открывай файл:

```text
~/dev/agy-patcher/build-app/Antigravity.app
```

Его можно открыть двойным щелчком в Finder и перетащить в Dock для дальнейшего
запуска одним нажатием. Закрепляй именно эту копию: существующий значок в Dock
может вести на исходное приложение из `/Applications`.

Также можно каждый раз использовать команду:

```sh
open -n ~/dev/agy-patcher/build-app/Antigravity.app
```

Повторно запускать патчер не требуется. Перед открытием копии закрой исходное
приложение. Копия сохраняет тот же идентификатор и может использовать общие
настройки и учётные данные; запуск двух экземпляров одновременно не проверялся.

## CLI agy: создание копии один раз

```sh
cd ~/dev/agy-patcher
python3 -B agy_patcher.py inspect --target cli
python3 -B agy_patcher.py patch --target cli --output-dir ./build-cli
```

После успешного создания проверь запуск:

```sh
~/dev/agy-patcher/build-cli/agy --version
```

## CLI agy: обычный запуск

Из любого каталога запускай изменённую копию по полному пути:

```sh
~/dev/agy-patcher/build-cli/agy
```

Аргументы передаются как обычно, например:

```sh
~/dev/agy-patcher/build-cli/agy --help
```

Обычная команда `agy` продолжает запускать исходный установленный CLI.
Патчер не меняет `PATH` или конфигурацию терминала.

## Если каталог build-app или build-cli уже существует

Патчер откажется его перезаписывать. Если копия уже создана, просто запускай её
по командам выше. При необходимости сделать ещё одну копию укажи новое имя,
например `--output-dir ./build-app-2`, и запускай приложение из нового каталога.
Удалять существующую копию для обычного запуска не нужно.

## После обновления

Обновление исходной установки не обновляет автоматически созданную копию.
Обновление самой копии может убрать патч. Для новой сборки потребуется новый
анализ и обновление патчера: текущая версия принимает только перечисленные ниже
контрольные суммы.

## Как вернуться к оригиналу

Закрой копию приложения и открой `/Applications/Antigravity.app`.
Для исходного CLI используй обычную команду `agy`.
Переустановка для такого возврата не требуется.

## Поддерживаемые сборки

| Цель | Версия | SHA-256 исходного бинарника |
| --- | --- | --- |
| CLI agy | 1.5.15 | 8097b24de18aba93324ee24d0d3f060906c58ba58562f4f1bd66f380906056a2 |
| Antigravity.app, language_server | 2.34.0 | bf66ad9f32ea50cf47686b3a4265cdd596d7c91a34de362f82264a4f52be4a87 |

По умолчанию проверяются `~/.local/bin/agy` и `/Applications/Antigravity.app`.
Другой путь можно задать через `--source /полный/путь`.
Версия по имени файла не угадывается: неизвестная контрольная сумма отклоняется.
Для приложения дополнительно проверяются `Info.plist` и `app.asar`.

## Содержимое созданных каталогов

| Каталог | Файлы |
| --- | --- |
| build-cli | agy, agy.original, manifest.json |
| build-app | Antigravity.app, language_server.original, manifest.json |

Файлы `*.original` — точные резервные копии исходных бинарников без права
исполнения. `manifest.json` содержит список изменений и контрольные суммы.
Резервный `language_server.original` сам по себе не возвращает исходную подпись
всему скопированному приложению; для исходной подписи используй оригинал в
`/Applications`.

## Какие инструкции меняются

CLI:

- В backend.IneligibilityFromResult по файловому смещению 0x2461364:
  ldrb w8,[x0,#8] заменяется на mov w8,#1.
- Во встроенной проверке backend.(*ServerBackend).handleAuthResult.func1
  по смещению 0x2497e28: ldrb w2,[x0,#8] заменяется на mov w2,#1.
- Существующие ветки, проверки ошибки и нулевого указателя сохраняются.

Приложение:

- В authclient.(*PersonalAuthValidator).Validate по смещению 0x25d3ec0:
  ldrb w3,[x0,#8]; tbz w3,#0,... заменяются на mov w3,#1; strb w3,[x0,#8].
- Таким образом локальный флаг результата проверки выставляется в 1, и
  выполнение проходит к существующему присоединению данных учётной записи.
  Предыдущая ветка обработки ошибки вызова сохраняется.

Байты до подписания меняются только в перечисленных местах. После подписания
дополнительно меняются структуры подписи и связанные метаданные. Патчер проверяет,
что секция машинных инструкций language_server или CLI при подписании не изменилась.

Эти изменения касаются локальной обработки результата проверки доступа.
Подписку, серверные разрешения и квоты они не предоставляют. Успешный доступ
к сервису и устранение конкретной региональной ошибки пока не проверены.

## Подпись и защита исходников

Для изменённой копии исходная подпись издателя заменяется локальной ad-hoc
подписью. У копии приложения при подписании сохраняются метаданные entitlements
и runtime. Для исполняемых файлов, загружающих локальные библиотеки,
добавляется com.apple.security.cs.disable-library-validation. Это снимает проверку
совпадения Team ID у загружаемых библиотек только в процессах копии приложения.
Системные настройки защиты и исходная установка не изменяются.
Это не подпись Google и не нотариализация Apple.

Патчер:

- не запрашивает sudo и не снимает карантинные или immutable-атрибуты;
- не обращается в сеть и не читает пароли или токены;
- не следует внешним ссылкам внутри .app;
- сверяет содержимое скопированного .app с источником до изменений;
- сохраняет контрольные суммы файлов приложения в manifest.json;
- не перезаписывает существующий каталог результата.

Само приложение и CLI при запуске сохраняют собственное сетевое поведение и
доступ к аккаунту. На создание копии приложения с резервным бинарником требуется
около 720 МБ, для CLI с резервной копией — около 460 МБ.

## Проверки

```sh
python3 -B test_patcher.py
```

Полный набор предполагает, что на Mac установлены обе поддерживаемые сборки.
Он создаёт временные копии в каталоге проекта и удаляет их после проверки.
Проверяются содержимое файлов, подпись и фактическая загрузка Electron в режиме
RunAsNode с коротким выражением, печатающим версию Electron. GUI не запускается,
профиль приложения не загружается, вход в аккаунт не выполняется. Для CLI дополнительно выполняется --version.

Только автономные проверки, без установленных приложений:

```sh
python3 -B -m unittest test_patcher.CoreTests -v
```

Все 9 проверок прошли 23 ноября 2026 года. Они покрывают точность изменений,
отказ для неизвестных и уже изменённых файлов, проверку контекста инструкций,
повреждение кода после подписания, защиту исходников и каталога результата,
запрет внешних ссылок, резервные копии и подписи обеих реальных сборок.

## Исправление сбоя при запуске после переподписи

Первоначальная схема подписи могла приводить к ошибке DYLD:
«mapping process and mapped file (non-platform) have different Team IDs».
Исправленная версия сохраняет исходные entitlements, добавляет исключение
проверки Team ID для исполняемых файлов с локальными библиотеками и заново
формирует подписи вложенных компонентов и внешнего .app. Успешная проверка
codesign теперь дополняется реальным запуском загрузчика Electron без GUI.

Описание исключения: [Apple: Disable Library Validation](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.cs.disable-library-validation).

Исправленная схема подписи применяется автоматически при создании новой копии.
